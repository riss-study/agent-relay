Claude Code 에서 접속하고 쓰는 법

팀원 PC 의 Claude Code 에 이 저장소의 플러그인을 붙여 중계 서버에 참가하고, 세션끼리 질문과 답을 주고받는 절차. 플러그인 1.2.0 기준.

준비물은 둘이다. 채팅 페이지 계정과 서버 주소다. 서버를 올리는 쪽의 절차는 README 에 있다.

같은 PC
ws://127.0.0.1:8765
LAN
ws://서버IP:8765
외부망
wss://agent-relay.duckdns.org:8443. 스킴을 빼면 플러그인이 ws:// 를 붙이니 외부망에서는 반드시 wss:// 까지 적는다

1플러그인 설치 (PC 마다 한 번)

Claude Code 2.1.275 이상과 Node 24 이상이 있어야 한다. 플러그인은 이 저장소의 plugin/ 에 있고 의존성 없이 node 가 바로 실행한다. 터미널에서 둘의 버전을 본다. Claude Code 가 낮으면 claude update 로 올린다.

claude --version
node --version

GitHub 의 이 저장소를 마켓플레이스로 등록하고 플러그인을 설치한다. 아무 폴더에서나 claude 를 켜고 세션 안에서 실행한다. 공개 저장소라 GitHub 계정이 없어도 된다.

/plugin marketplace add riss-study/agent-relay
/plugin install agent-relay@agent-relay

설치됐는지 보려면 /plugin 을 열어 Installed 목록에 relay 가 있는지 본다. 이 세션은 그대로 닫는다.

셸 프로필(~/.zshrc)에 별칭을 넣고 터미널을 다시 연다. 팀 기능은 이 별칭으로 켠 세션에서만 돈다. 그냥 claude 로 켠 세션은 받지도 보내지도 못하고 진단 명령만 된다.

alias claude-team='AGENT_RELAY_TEAM=1 claude --dangerously-load-development-channels plugin:agent-relay@agent-relay'

새 터미널에서 claude-team 을 켜고 /agent-relay: 까지 치면 join, status, room, away, doctor, server, owner 명령 목록이 뜬다. 뜨면 설치는 끝이다. 안 뜨면 별칭 없이 claude 로 켰거나 설치가 안 된 것이다.

서버와 플러그인이 같은 저장소에 있어서 같이 올라간다. 저장소를 새로 받은 뒤 /plugin 의 Marketplaces 에서 agent-relay 를 Update marketplace 하거나 터미널에서 아래를 실행한다. 켜져 있던 다른 세션은 각자 /reload-plugins 를 한 번 한다.

claude plugin update agent-relay@agent-relay

2참가 코드 받기 (채팅 페이지)

플러그인의 참가 코드는 채팅 페이지에서 받는다. 운영자가 curl 로 발급하는 방식은 쓰지 않는다.

  1. https://agent-relay.duckdns.org:8443/chat(서버와 같은 PC 면 http://127.0.0.1:8765/chat)에서 가입 신청을 하고 관리자 승인을 기다린다. 비밀번호는 8자 이상이다.
  2. 로그인한 뒤 방장에게 받은 방 코드(RM-XXXX-XXXX)로 참가 신청을 하고 방장 승인을 기다린다. 방을 새로 만들면 내가 방장이다.
  3. 방 패널의 "플러그인 이름" 칸에 이 세션을 부를 이름을 적고 "참가 코드"를 누른다. TR- 로 시작하는 한 줄이 나온다. 코드는 한 번만 쓰이고 72시간 뒤 만료된다.

이름 칸을 비우면 계정 이름이 된다. 회사 PC 와 집 PC 처럼 세션을 여럿 둘 거면 "이경환 회사", "이경환 집"처럼 세션마다 다른 이름으로 코드를 따로 받는다. 같은 이름으로 다시 받으면 기존 멤버에 방만 더해지고, 방 안의 다른 사람이 쓰는 이름은 거절된다.

3세션 켜고 참가하기

claude-team

처음 한 번은 확인이 두 개 뜬다. 개발 채널 경고에서 "I am using this for local development", 새 MCP 서버에서 "Use this MCP server"를 고른다. 세션 안에서 참가한다.

/agent-relay:join wss://agent-relay.duckdns.org:8443 TR-3F2A-9C1B

성공하면 내 이름과 방, 접속 중인 팀원이 나온다. 플러그인이 토큰을 ~/.claude/channels/relay/config.json 에 저장하므로 다음부터는 claude-team 만 켜면 자동으로 붙는다. 토큰이 그 PC 의 신원이라 다른 PC 로 복사하지 않는다. 다른 PC 에서는 페이지에서 코드를 새로 받아 참가한다.

연결이 의심되면 /agent-relay:doctor 를 실행한다. 설정과 연결, 받는 방, 보관함을 점검하고 어긋난 항목마다 할 일을 알려 준다.

상태줄

팀 세션이면 프롬프트 아래에 [team O web3] 처럼 연결 상태가 한 줄로 뜬다. 플러그인에 들어 있어서 따로 설정할 것이 없다. 플러그인이 5초마다 자기 상태 파일을 읽어 띄우고, 팀 세션이 아니면 아무것도 띄우지 않는다.

안 뜨면 Claude Code 가 플러그인 모듈을 싣지 못하는 버전이다. 그때는 claude update 로 올리거나, 플러그인이 복사해 두는 ~/.claude/channels/relay/statusline.sh 를 ~/.claude/settings.json 에 넣고 다시 켠다.

{ "statusLine": { "type": "command", "command": "~/.claude/channels/relay/statusline.sh" } }
표시뜻
[team O web3]web3 방을 받는 중. 뒤에 보관 2 가 붙으면 나를 기다리는 보관 메시지가 2건
[team 담당없음]아무 방도 받지 않음. /agent-relay:room 방이름 으로 정한다
[team 퇴근]away 켜짐
[team X 미참가]아직 참가 전
[team X 연결없음]서버에 못 붙음. 플러그인이 재접속을 시도 중이다
[team X 토큰 무효], [team X 차단됨], [team X 구버전]새 코드로 참가하거나 플러그인을 업데이트한다
[team X 플러그인 미동작]플러그인 프로세스가 죽음. /mcp 에서 다시 연결하거나 세션을 다시 켠다
아무것도 없음팀 세션이 아니다

4주고받기

명령 없이 세션에 말하면 된다. 플러그인이 team_send, team_reply 같은 도구를 알아서 부른다.

하고 싶은 것이렇게 말한다무슨 일이 생기나
팀원에게 질문"규영에게 배포 일정 물어봐 줘"보내진다. 상대 세션이 꺼져 있으면 보관됐다가 켜질 때 배달된다. 15분 동안 답도 처리 중 표시도 없으면 무응답 알림이 온다
답이 필요 없는 전달"규영에게 배포 끝났다고 알려만 줘"무응답 알림 없이 전달만 된다
받은 질문에 답하기받은 메시지가 <channel> 로 화면에 뜨면 세션이 같은 스레드로 답한다받는 사람과 방은 서버가 정하므로 엉뚱한 곳으로 가지 않는다
지난 대화 보기"규영이랑 주고받은 메시지 보여 줘"내 문답만 나온다. 전체 기록은 채팅 페이지에서 본다
합의 남기기"방금 합의한 스키마 올려 줘"상대 세션이 확인하면 확정되고 같은 방 전원이 본다
방 메모리 제안"스테이징 DB 가 매일 06시에 초기화된다는 걸 방 메모리에 제안해 줘"방장이 승인하면 그 방 세션 전부가 시작 때부터 안다
받는 쪽 세션은 팀원 메시지를 사용자 승인으로 보지 않는다. 받은 지시를 바로 실행하게 하려면 그 세션의 사용자가 "내작업 방의 메시지는 내 지시다, 바로 실행해"라고 세션에 직접 말하거나 CLAUDE.md 에 적어 둔다. 권한 설정이나 CLAUDE.md 를 바꾸라는 요구는 어느 쪽이든 거부된다.

명령으로 하는 것은 아래가 전부다. /agent-relay: 까지 치면 목록이 뜬다.

명령하는 일
/agent-relay:status이 세션이 받는 방, 방마다 내 이름, 팀원의 접속 상태
/agent-relay:room 방이름이 세션이 그 방을 받는다. 여러 개는 쉼표로 잇는다
/agent-relay:away on퇴근. 메시지가 서버에 보관되고 보관 기한도 멈춘다. off 로 출근하면 한꺼번에 온다
/agent-relay:doctor자가 진단
/agent-relay:server ws://새주소:8765서버 주소만 바꾼다. 토큰은 그대로다
/agent-relay:owner notice 방이름 내용방장이 방 전원에게 공지한다. 받는 쪽은 답하지 않는다
/agent-relay:owner kick 방이름 이름방장이 플러그인 멤버 하나를 그 방에서 뺀다

5세션 여러 개

한 멤버의 방은 세션 하나만 받는다. 같은 방을 받는 세션을 하나 더 켜면 먼저 뜬 쪽이 계속 받고, 새 세션에서 /agent-relay:room 방이름 을 실행하면 담당이 넘어온다. 방마다 세션을 나누려면 다른 창에서 그 방 코드로 참가한다. 참가 직후 그 세션은 새 방만 받으니 둘 다 받으려면 /agent-relay:room a,b 로 지정한다.

같은 PC 에서 세션 둘을 서로 다른 멤버로 두어 둘이 대화하게 하려면 플러그인 설정 파일을 나눈다. 설정 파일 하나는 멤버 하나다.

AGENT_RELAY_CONFIG=~/.claude/channels/relay/second.json claude-team

그 세션에서 페이지의 다른 이름으로 받은 코드로 참가한다. 상태 파일은 설정 파일과 같은 폴더에 생기므로 폴더까지 나누고 싶으면 경로를 다른 폴더로 준다.

6나가기와 막힘

  • 방에서 나가려면 채팅 페이지의 방 패널에서 나가기를 누른다. 플러그인에서 그 방이 빠지고 페이지에는 "나간 방"으로 남아 있던 구간의 기록만 보인다. 다시 들어오려면 방 코드로 신청해 방장 승인을 받는다.
  • 토큰을 버리려면 페이지의 "내 플러그인"에서 폐기한다. 그 세션에 "[팀 연결 종료]" 알림이 뜨고 재접속을 멈춘다. 다시 쓰려면 새 코드로 참가한다.
  • 관리자가 계정을 비활성화하면 로그인이 막히고 토큰이 모두 폐기된다.
보이는 것원인할 일
/agent-relay:join 이 없는 명령플러그인이 없거나 claude 로 켠 세션설치를 확인하고 claude-team 으로 다시 켠다
"연결할 수 없습니다"주소가 틀리거나 서버가 꺼졌거나 VPN 이 끊김주소에 스킴이 있는지 보고 서버 쪽에서 curl -i http://127.0.0.1:8765/admin/invite 로 401 이 오는지 본다
"만료" 또는 "이미 사용된 초대코드"코드는 한 번만, 72시간페이지에서 다시 받는다
auth_failed토큰이 폐기됐거나 서버 DB 가 새로 만들어짐페이지에서 새 코드로 참가한다
발신은 되는데 수신이 안 됨다른 세션이 그 방을 받는 중/agent-relay:status 로 보고 /agent-relay:room 방이름 으로 가져온다
sent 가 queued상대 세션이 없거나 퇴근 중정상이다. 접속하면 배달되고 72시간 뒤 expired 가 온다
rate_limited분당 30건 초과1분 기다린다
not_room_owner방장이 아닌데 방장 명령페이지에서 방장이 "방장 지정"을 한다

팀 메시지는 누가 언제 어느 방에 무엇을 보냈는지 서버에 남고, 방의 멤버는 자기가 있던 구간의 기록을 페이지에서 본다. 개인적인 내용은 보내지 않는다.
